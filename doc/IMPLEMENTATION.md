# Lumin MVP 実装メモ

## 採用した構成

大会での再現性を優先し、SwiftUIの単一アプリ内に教師モードと生徒モードを実装した。教師端末がMultipeerConnectivityのadvertiser、生徒端末がbrowserとなる。通信は `.required` の暗号化設定を利用し、探索情報には載せない4桁の参加コードを招待時に照合する。

```text
生徒UI
  ↓ 生の解答
GemmaService / LearningAnalyzing（端末内）
  ↓ AnalysisEvent（最小化済み）
MultipeerConnectivity
  ↓
教師UI → ClassAnalytics → LessonPlanGenerator → 教師が編集・採用
```

## MVPでのAIの扱い

Gemma 3 1B ITの4bit量子化済み `.litertlm` モデルを、Google LiteRT-LM 0.15.0で端末内実行する。誤答時には問題・正答候補・生徒の回答・誤概念候補・ヒント段階をGemmaへ渡し、JSON Schema制約付きで誤概念とヒントを生成する。通信処理は介在せず、生徒の入力は端末外へ出ない。

教師向け授業案もGemmaで生成するが、入力は `ClassSummary` の匿名集計だけに限定する。GPU初期化に失敗した場合はCPU、モデル未配置・推論失敗・不正なJSONの場合はルールベースの安全な案へフォールバックする。

実装済みの推論順序は以下の通り。

1. LiteRT-LMでGemmaをMetal GPUへロード
2. JSON Schema制約付きで構造化出力を生成
3. 正答漏洩チェックと候補外ラベルの拒否
4. 出力が不正な場合はルールベースへフォールバック
5. 推論時間と利用バックエンドをUIに表示

## デモ手順（約3分）

1. 先生端末で「先生として始める」→「小テスト配信」→配信開始。
2. 生徒端末で「生徒として参加」→見つかった先生端末へ接続。
3. 第1問に `2` と回答し、「傾きと切片の混同」に対応したヒントを表示。
4. `3` と再回答して次へ進む。
5. 先生端末の「理解の現在地」で匿名シグナルの反映を確認。
6. 回答数が足りなければ「大会デモ用データを読み込む」。
7. 「次の10分」で集計から案を再生成し、一文を修正して採用。
8. ネットワークモニタ等で外部通信がないことを補足する。

## 既知の範囲

- 教材作成画面と教材の取り込みは未実装。
- 匿名参加トークンは授業セッションごとに再生成される。
- 端末間通信はApple端末同士を対象とする。
- 誤概念分類は一次関数のサンプル教材に限定している。

## 実運用向けに追加した範囲

- 授業ごとのUUIDを問題配信と分析イベントへ付与し、別授業の結果を受け入れない。
- 生徒端末の未送信イベントを永続キューへ保存し、再接続時に再送する。
- 教師端末はイベントIDで受領確認を返し、重複イベントは集計しない。
- 配信終了を生徒へ通知し、教師端末には匿名集計と採用した授業案を最大100授業保存する。
- 進行中の教師セッションはイベント受信・授業案採用ごとに復旧用スナップショットを更新し、異常終了後は履歴へ回収する。
- 履歴はアプリ内で確認・個別削除できる。解答本文やヒント本文は保存しない。
