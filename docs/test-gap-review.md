# フロントエンド・バックエンドの追加テスト調査

調査日: 2026-09-30

## 結論

追加する価値が高いテストがある。最優先は、生徒の結果送信と集計値、HTTP ルーター全体の認証・重複排除、セッションの開始・終了に伴う状態管理である。また、既存フロントエンドテストを CI で実行する必要がある。

この調査は実装と既存テストの静的な照合に基づく。テストの追加・実行、カバレッジ計測は行っていない。以下の未検証リスクは、不具合を再現・確定したという意味ではない。

## 既存テストで確認できること

- フロントエンド: 15 個のテストファイル。ロール選択、参加の基本操作、設定画面、モデル切り替え、チャット、授業案生成、Markdown、日本語 IME などを検証している。
- `MobileInput.test.tsx:36` は結果送信失敗時に問題を保持し、同じイベント ID で再試行することを検証済み。このケースの単純な追加は不要。
- `ContractLocks.test.tsx` は解答判定・ヒント生成の IPC 引数と、ヒント生成失敗時のフォールバックを検証済み。
- バックエンド: 解答の正規化、誤概念分類、集計、AI 出力検証・ヒントの安全性、永続化、送信待ちキュー、モデル情報などに単体テストがある。
- `network/server.rs` には参加登録、解答イベントのセッション ID 検証、正常送信、クイズ配信、手動参加から認証付き結果送信までのテストがある。

## CI とテストの組み方

`.github/workflows/ci.yml` のフロントエンドジョブは依存導入と `bun run build` のみで、`bun run test:run` がない。既存テストが PR の判定に使われるよう、これを追加する優先度は高い。Rust の通常テストはすでに CI で実行されている。

まずフロントエンドの送信イベントとサーバ側の重複排除・認証を追加し、次にセッション状態とダウンロード失敗を検証する。HTTP テストは本番ルーターとローカルサーバを使い、モデルや外部サービスのダウンロードに依存させない。セッションの広告・ダウンロードの通知などは、必要に応じて境界を分離して失敗を注入できるようにする。

最後に「先生が開始→生徒が参加→誤答とヒント→正答→結果送信→先生の集計更新→終了」を通す結合テストを置くと、画面・IPC・HTTP の契約をまとめて保護できる。既存の参加・HTTP 結合テストを土台にし、外部モデルを必要としない構成を優先する。

## 実装状況

2026-09-30 にプランに基づく一部を実装した。

- StudentQuiz の再挑戦イベント、送信失敗後の最終問題再試行、TeacherDashboard のイベント後の集計更新、TeacherSessionControl の開始・終了・開始失敗、viewport 更新、ModelManager の進捗・完了通知をテストに追加した。
- 本番 HTTP ルーターでの認証、参加コード更新、終了後のセッション解決拒否、未登録参加者の拒否、イベント重複排除、不正な参加応答、壊れた履歴 JSON の保持を Rust テストに追加した。結果送信時の 403/500 も失敗として返ることを確認した。不正な参加応答の成功扱い、広告開始失敗時の HTTP サーバ残存を修正し、セッション終了時に推論側のクイズ状態も解除する。
- ダウンロードの 401/403 非再試行、再試行上限、キャンセル、チェックサム不一致、既存ファイル再利用をローカル HTTP テストで検証した。既存ファイルの再利用テストで HEAD 応答の `Content-Length` が取得できず不要な再ダウンロードが起きる不具合を確認し、ヘッダーを直接読むよう修正した。
- Frontend CI に `bun run test:run` を追加した。Linux 向け Tauri WebDriver の二端末 E2E を追加し、先生が開始したクイズへ生徒が localhost 経由で参加し、誤答後にヒントを使って再挑戦した結果で先生側の集計を更新し、配信を終了するまでを実アプリで確認する。
- ローカル検証: `bun install --frozen-lockfile`、`bun run build`、frontend 18 ファイル・97 テスト、`cargo check`、`cargo clippy -- -D warnings`、`cargo fmt -- --check` が成功。Rust は 250 テスト中 231 成功・19 ignored。
- E2E はこの環境に WebKitWebDriver と Xvfb がなく完走できなかった。CI ジョブはこれらを導入して二つの Tauri アプリプロセスで実行する。CI 上の E2E 結果は未確認。
- 未実装の候補: `start_session` のポート競合・mDNS 広告失敗を注入するテスト、既存セッション復元や参加者ポーリング停止の UI テスト。失敗時の広告・サーバ後片付け処理は修正したが、実アプリ依存を置き換えるテスト境界はまだない。
