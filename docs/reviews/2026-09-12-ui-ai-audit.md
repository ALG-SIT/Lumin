# UI・AIコンテキストの修正確認（2026-09-12）

## 実画面

Safariの開発画面と、ビルドしたmacOS版 Lumin.app（1024×720）を操作して確認。

- 修正前：AIチャットへの移動だけでページのスクロール位置が途中へ飛び、上部バーが消えた。モデル管理がチャットの上に常時表示されていた。
- 修正後：モデル管理を独立タブへ移動。チャットを開いてもページを移動せず、参加コード・履歴・入力欄が標準ウィンドウ内に収まる。履歴更新時のスクロールは履歴要素のみ。過去メッセージを読んでいる間は位置を維持する。
- 教材選択：縦積みの教科一覧を2列にし、6教材と配信ボタンを標準ウィンドウ内に表示。
- 授業案：欠けていた編集レイアウトを追加。4段階の編集欄と採用ボタンまで標準ウィンドウ内に表示。
- 生徒参加画面の入力欄と参加ボタンが表示できることを確認。
- 検証用に開始した配信は終了済み。タブを往復しても配信状態が復元されることを確認。
- 狭い画面向けの既存メディアクエリは維持。モバイル端末・ソフトウェアキーボード表示中の実機確認は未実施。

## AI経路

- 教師チャット：常にnullだった教材をバックエンドの配信状態から取得。参加数だけでなく、正答率・再挑戦成功率・ヒント数・誤概念・教材の問題と説明・会話履歴をプロンプトへ渡す。未収集と0%を区別する指示を追加。
- ヒント：概念名のみの入力を問題本文・直前の解答・段階・既出の教材ヒントへ変更。回答漏洩ガードを実際の返却経路に適用。未ロード・失敗・空出力・漏洩は教材ヒントへ戻す。
- 採点：共通の正規化による正誤判定を使用。正答は誤概念なし。AIのm0等のコードを候補ラベルへ変換し、候補外・生成失敗はルール採点へ戻す。
- 授業案：誤概念のフィールドをRustと同じname/count/shareへ統一し、教材も渡す。生成失敗時も教材・集計から案を作る。回答0件の代替案で「誤答が多かった」と記述しない。
- 単独のJSONコードブロックは解析できるようにし、周囲に任意の文章がある出力は引き続き拒否。
- モック出力を実際のAI回答として表示しない。教師チャットは未ロードを明示。
- 日本語IME変換中のEnterではチャットを送信しない。
- 授業案の初期生成が、既に入力した教師の編集内容を上書きしない。
