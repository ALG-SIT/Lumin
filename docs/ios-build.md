# iOS Build Guide

Verified on a physical iPhone 17 (iOS 27) with Xcode 27. The minimum supported
iOS version is **26.0**.

## Prerequisites

- macOS with Xcode 26 or newer, and its command line tools selected:
  `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
- An Apple ID added in Xcode (Settings → Accounts). Automatic signing creates
  the development certificate and provisioning profile from it; a free Apple ID
  works, with a 7-day profile.
- `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`
- `brew install cocoapods xcodegen libimobiledevice`
  - `cocoapods` and `xcodegen` are needed by `tauri ios init`. The Tauri CLI
    offers to install them itself, but its `gem install cocoapods` path needs
    `sudo`, so install them with Homebrew first.
  - `libimobiledevice` provides `idevicesyslog`, which `tauri ios dev` uses to
    stream device logs. Without it the command installs and launches the app
    and *then* aborts the session.

## Signing

Nothing about signing is tracked in git, because the team ID is per-developer.
Export your team ID and let the setup script write the untracked files:

```bash
export APPLE_DEVELOPMENT_TEAM=XXXXXXXXXX
bun run ios:init      # ios:signing → tauri ios init → ios:signing
```

Your team ID is the `OU` field of your signing certificate:

```bash
security find-certificate -c "Apple Development" -p | openssl x509 -noout -subject
```

`bun run ios:signing` (run by `ios:init`, and on its own whenever you need it)
writes two gitignored files:

| File | Why it is needed |
| --- | --- |
| `src-tauri/tauri.ios.conf.json` | Tauri merges it into `tauri.conf.json` for iOS builds. `$APPLE_DEVELOPMENT_TEAM` alone is not enough: Xcode's "Build Rust Code" phase shells out to `tauri ios xcode-script`, which re-reads the config in a sanitized environment and otherwise fails with `` `apple.development-team` is empty ``. |
| `src-tauri/gen/apple/ExportOptions.plist` | `tauri ios init` writes one that only sets `method`, and `xcodebuild -exportArchive` then refuses the app with "requires a provisioning profile". Tauri has no configuration for this file, so the script patches it. |

`src-tauri/gen/apple/` as a whole is gitignored: `tauri ios init` bakes the
signing team into the generated Xcode project, and — unlike `Info.plist` — it is
**not** regenerated by later `tauri ios dev` runs, so a committed copy would
pin everyone to whoever generated it. Regenerate it with `bun run ios:init`
after changing `tauri.conf.json` values that feed the Xcode project, such as
`bundle.iOS.minimumSystemVersion`.

## Run on a device

```bash
bun run ios:dev       # tauri ios dev --host
```

`--host` makes the Vite dev server listen on the LAN address the device can
reach. On the first install, iOS refuses to launch an app signed by a personal
team until you trust it: **Settings → General → VPN & Device Management →
Developer App → trust**.

## Simulator and release builds

```bash
bun run tauri ios dev --open        # open the project in Xcode instead
bun run tauri ios build             # release IPA
```

## UIScene life cycle

Apps built against the iOS 26 SDK or newer must adopt the UIKit scene life
cycle, or UIKit traps at launch with `EXC_BREAKPOINT` in
`__UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`. `tao` ships a
`TaoSceneDelegate`, but it only registers
`application:configurationForConnectingSceneSession:options:` when the app's
Info.plist enables multiple scenes, so `src-tauri/Info.ios.plist` sets:

```xml
<key>UIApplicationSceneManifest</key>
<dict>
    <key>UIApplicationSupportsMultipleScenes</key>
    <true/>
</dict>
```

See Apple's [TN3187](https://developer.apple.com/documentation/technotes/tn3187-migrating-to-the-uikit-scene-based-life-cycle).

## On-device inference

iOS cannot load the ONNX Runtime shared library that the desktop builds ship in
`src-tauri/runtime/`, so the iOS target links a prebuilt **static** ONNX
Runtime instead and runs the CoreML execution provider. This is wired up in
`src-tauri/Cargo.toml` by target rather than by cargo feature, because cargo
features cannot vary per target and the Tauri CLI forwards the crate's default
features to the iOS build verbatim:

```toml
[target.'cfg(not(target_os = "ios"))'.dependencies]
ort = { version = "2.0.0-rc.13", features = ["load-dynamic"] }

[target.'cfg(all(target_os = "ios", target_arch = "aarch64"))'.dependencies]
ort = { version = "2.0.0-rc.13", features = ["half", "coreml", "download-binaries"] }
```

`ort-sys` downloads the iOS static library on first build and links
`CoreML.framework` automatically. `inference::runtime::selected` therefore
defaults to CoreML on iOS: the WebGPU provider is a separate shared library
registered at runtime, which cannot be bundled on iOS.

The desktop native libraries stay out of the IPA because `bundle.resources` is
declared only in the per-platform desktop configs
(`tauri.macos.conf.json`, `tauri.windows.conf.json`, `tauri.linux.conf.json`).
Note that `gen/apple/assets/` is copied into the app wholesale by the Xcode
project and is *not* pruned when `bundle.resources` shrinks, so delete it if
stale native libraries reappear in the bundle.

Models are downloaded in-app into the sandbox (`app_data_dir/models`), so there
is nothing to bundle. Measured throughput for Gemma 3 1B INT4 on an iPhone 17
was roughly 7.5 tokens/second, after about 20 seconds of CoreML model
compilation on the first request of a session.

## Local network permission

Classroom discovery needs Bonjour, declared in `src-tauri/Info.ios.plist`:

- `NSLocalNetworkUsageDescription`
- `NSBonjourServices`: `_lumin-class._tcp`

## Vendored DNS-SD plugin

`vendor/tauri-plugin-dns-sd` is a local fork of `tauri-plugin-dns-sd` 0.1.0,
wired in through `[patch.crates-io]` in the workspace `Cargo.toml`. The
published crate's Swift source does not compile against the Tauri iOS API:
`JSObject` values must conform to `JSValue`, which `Int64` does not, and the
`NSNull` fallbacks for `host`/`port` need an explicit cast. The fork changes
only those lines. Upstream has no release with the fix yet.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `` `apple.development-team` is empty `` | `src-tauri/tauri.ios.conf.json` missing — run `bun run ios:signing`. |
| `exportArchive ... requires a provisioning profile` | `ExportOptions.plist` not patched — run `bun run ios:signing`. |
| Launch denied, "profile has not been explicitly trusted by the user" | Trust the developer app in Settings (see above). |
| `Failed to install libimobiledevice` at the end of `ios:dev` | `brew install libimobiledevice`. |
| App still reports an old `MinimumOSVersion` | The Xcode project is stale; `bun run ios:init` to regenerate. |

Device crash logs can be pulled without Xcode:

```bash
xcrun devicectl device info files --device <UDID> --domain-type systemCrashLogs --search Lumin
xcrun devicectl device copy from --device <UDID> --domain-type systemCrashLogs \
  --source <name>.ips --destination ./crash.ips
```
