# iPhone UI検証記録

2026-09-13。まずiPhone 17eシミュレータ（390 × 844 pt）、iOS 27 / Xcode 27 beta 6 のネイティブアプリをXCTestで操作した。Vite開発サーバーから修正を反映して再確認した。その後、Macに接続した物理iPhone 17（402 × 874 pt）でも同じ主要導線をUI Test Runnerから再確認した。

Xcode 27ではSimulatorの操作画面がDevice Hubに変わっている。今回の環境ではDevice Hubのアクセシビリティ取得がタイムアウトしたため、ユーザー承認のもとXCTestとsimctlのスクリーンショットで検証した。

参考: [Apple Device Hub](https://developer.apple.com/documentation/xcode/device-hub/)

## 確認した画面・操作

- 役割選択、先生の概要・セッション・小テスト選択と配信・レッスンプラン・AIチャット。
- チャットの日本語入力、キーボード表示、設定の開閉、タブ切り替え後の下書き保持。
- 設定のモデル一覧、下部のシステム情報、スクロール後の閉じる操作。
- 生徒の教室検索・手動入力・キーボード表示。
- デモ開始から完了、結果の下部までのスクロール。
- 生徒の小テスト、誤答、ヒント、次のヒント、キーボードを開いたままの送信、5問完了、参加画面への復帰。
- 横向きの先生画面・チャット。XCTestのアプリ画像に黒領域が入るため、simctlで直接取得して表示を確認。

## 修正

| 箇所 | 問題 | 対応 |
| --- | --- | --- |
| 全画面 | iOSのキーボードで画面全体が押し上がり、上部操作が見えなくなる | Visual Viewportに表示領域を合わせ、内容領域でスクロール |
| 全画面 | ノッチ・ホームインジケーター付近の表示領域 | viewport-fitと上下左右のsafe areaを反映 |
| ヘッダー | 役割・切り替え・モデル状態の折り返しと右端の見切れ | 狭い画面では2段に配置、モデル状態の幅を制限 |
| 役割選択 | 大きなカードによりデモ選択が初期表示の下に隠れる | モバイル時のカードと余白を縮小 |
| 設定 | 閉じるボタンが縦に伸びる | 折り返しと縮小を防止、スクロール時もヘッダーを保持 |
| モデル一覧 | 名前・説明が極端に狭く、単語ごとに改行 | モバイル用の行構成と余白に変更 |
| システム情報 | 長いパスが狭い列で縦に伸びる | モバイル時は1列に変更 |
| iPhoneの保存先表示 | UUIDを含む内部パスが何行も表示され、読み上げ対象にもなる | 「このiPhone内（アプリ専用領域）」へ置き換え、内部パスをアクセシビリティ階層からも除外 |
| 設定の開閉 | 元のタブ・チャット下書き・生徒入力が消える | 元画面をアンマウントせず非表示にして保持 |
| 先生タブ | タブ切り替えでチャット下書きが消える | チャットを保持 |
| チャット | 提案ボタンが複数行を占め、会話領域を圧迫 | 横スクロール化、入力中は補助表示を畳む |
| 横向きチャット | 説明部分が高さを占めて入力欄が隠れる | 高さ500px以下では補助表示を畳む |
| デモ完了・エラー | 戻る操作が小さい標準ボタンになる | 共通のセカンダリーボタンに統一 |
| 先生タブ・設定操作 | タップ領域が小さい | 主な操作の高さを44px以上に変更 |
| レッスンプラン | 小さい入力文字 | 16pxに変更し、フォーカス時の自動拡大を避ける |
| 生徒解答 | キーボードの下へ確認ボタンが隠れる | 入力欄をスクロール領域の中央へ移し、入力中の下部余白を調整 |
| 生徒解答 | 日本語変換確定のEnterで送信し得る | composition / keyCode 229を除外 |
| 教室検索 | 完了後も検索中の説明、再試行がない | 検索状態を表示し、再検索を追加 |
| 教室参加 | 処理中の状態が不明、重複操作が可能 | 「参加中…」を表示し、重複実行を抑制 |
| 手動入力 | 不正なポート番号が送信できる | 1–65535の整数に限定、入力ラベルとキーボードを調整 |

## 検証の限界・残件

以下は初回検証時点の記録。手動参加と実モデル推論は、後続の[追加検証と修正](ios-inference-network-ux.md)で対応した。

実際のサーバーに正しい参加コードで手動参加すると403になった。手動入力ではsession UUIDを送らない一方、サーバーの認証はUUIDヘッダーも要求している。認証を弱める変更は行っていない。

生徒の小テスト画面を確認する際は、127.0.0.1:18765の一時HTTPサーバーで参加応答だけを返した。問題は同じアプリで配信開始した実データを利用した。この検証は別端末間の教室参加・結果共有の成功を示さない。

初回検証ではモデル未導入だったが、後続検証では物理iPhone上のGemma 4 E2B INT4で教師チャット、誤答ヒント、レッスンプラン生成を実行した。iOS 27 betaの単一物理端末での確認であり、他のiOS版・文字サイズ拡大は未検証。

## チェックと証拠

`bun run check`、`bun run test:run`（81件）、`bun run build`、`git diff --check`を実行。ビルドには既存の500kB超チャンク警告がある。

ネイティブの初期ビルド・インストールは `bun run tauri ios dev 'iPhone 17e' --no-watch` で実施。UI操作はXCTest。スクリーンショットとテストコードはローカルの `.build/ios-ui-audit/`（git管理外）に保存した。`before/` が修正前、`final/` が最終確認。

XCTestは主要フロー2件（計116.6秒）と横向き確認1件が成功。横向きチャットの修正後画像は `final/27-landscape-chat-direct.png`。

物理端末では、役割選択、先生4画面、設定、生徒参加、デモ、キーボード、横向き、誤答・実モデルヒント・再回答・5問完了を実行した。さらにMacの先生アプリへWi-Fi経由で参加して5問を送り、Mac側で参加者1人・全5回答・初回正解率100%が表示されることを確認した。結果は `physical-overview-3.xcresult`、`physical-classroom-2.xcresult`、`physical-mac-network.xcresult`、設定修正後は `physical-final-ui.xcresult` に保存した。
